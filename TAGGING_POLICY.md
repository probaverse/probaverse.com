# Tagging Policy

This site uses `tags` as the main content taxonomy.
For now, `categories` can remain empty unless a broader section structure is introduced later.

## Goals

- Keep tags consistent across posts.
- Make related posts easy to discover.
- Avoid near-duplicate tags that mean the same thing.

## General Rules

- Use `tags`, not `categories`, as the primary classification field.
- Prefer 4 to 6 tags per post.
- Prefer stable, reusable tags over one-off tags.
- Use short noun phrases rather than sentences.
- Keep wording consistent. Do not alternate between near-synonyms like `distribution fitting` and `fitting distributions`.
- Preserve official capitalization for proper names like `R` and `CRAN`.
- Use lowercase for general concepts and topic phrases like `probability distributions`.

## Tag Selection Pattern

When a post is about a probaverse package release, choose tags from these groups:

1. Ecosystem:
   `probaverse`
2. Language or platform:
   `R`
3. Release channel, when relevant:
   `CRAN`
4. Core statistical topic:
   `probability distributions`
5. Package-specific capability:
   examples include `distribution objects`, `distribution manipulation`, `distribution fitting`
6. Optional application or method tag:
   examples include `quantiles`, `risk modelling`, `hydrology`

Not every post needs all six groups.
Only include the optional application or method tag when it is genuinely central to the post.

## Canonical Tags

Use these exact tags when they fit:

- `probaverse`
- `R`
- `CRAN`
- `probability distributions`
- `distribution objects`
- `distribution manipulation`
- `distribution fitting`
- `quantiles`
